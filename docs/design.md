# 设计记录 · claude-chan-pet

## 1. 任务与约束

用户给了一份 Claude 娘三视图设计稿，要求"**模仿 dsh-pet 做一个，给 Claude Code 用**"。所以三件事要同时满足：

1. 用设计稿的立绘（不是网上找的图）；
2. 形态对标 dsh-pet（透明悬浮桌宠、跟着会话状态反应、可拖拽甩抛）；
3. 宿主不是 DeepSeek Harness，而是 Claude Code。

## 2. 与 dsh-pet 的对照

| 维度 | dsh-pet | 本项目 | 取舍理由 |
| --- | --- | --- | --- |
| 宿主 | DSH（cordis 插件框架） | Claude Code（hooks） | 宿主不同，接入方式只能换成 hook → 事件文件 |
| 外壳 | 三套：浏览器 overlay / 独立 Electron 透明窗 / standalone | 一套：独立 Electron 透明窗 | Claude Code 没有可注入的网页 UI，浏览器 overlay 无意义 |
| 动画素材 | 97 段 VP9-alpha 透明 webm（AI 生成的护城河） | 程序化形变（呼吸 / Q弹 / 行走 / 抛掷） | 没有生成管线，也不该假装有 |
| 事件联动 | DSH 会话事件 → 6 档 workStatus 动画 + 文案 | Claude Code hooks → 6 档状态 + 表情 + 文案 | 语义照抄：同一套档位划分 |
| 碎碎念 | 调当前会话模型（默认开） | 本地台词池（零成本） | 用户强调 token 成本；要接模型再加 |
| 配置 | JSONC 三层合并（实例 / 全局 / 条目） | JSON 用户层覆盖内置默认 | 用得上的是"整段替换"这一条口径 |
| 物理 | 纯函数共享给两端 | 纯函数在主进程 | 只有一套外壳，不需要跨端共享 |

## 3. 素材管线（关键决策）

设计稿是**平底奶白图，无 alpha**。三条路：

- 直接放透明窗 → 露出奶白方块，否决；
- 颜色抠图（chroma key）→ 白裙子会被一起吃掉，否决；
- **裁切 + 从边缘洪水填充** → 采用。

洪水填充只抹掉"与裁切边缘连通、且颜色接近纸底（容差 46）"的像素，白裙子是被描边包围的封闭区域，所以安全。实测透明占比：三个视图 33%~36%，表情格 12%~19%，都在合理区间（脚本对 >75% 会报警，说明立绘被吃掉了）。

坐标不是猜的：`analyze-sheet.py` 用行列投影量出内容带与格子边界——

- 立绘带 y70–515，正/侧/背三视图 x 分别 74–454 / 518–820 / 860–1205
- 表情带 y613–731，正好 10 个等宽格子

## 4. 状态表

档位划分照抄 dsh-pet 的 workStatus（thinking / working / result / waiting / success / error），文案结构也照抄（每档多句备选、播放随机抽）。差别在于 dsh-pet 每档是一段动画，这里是"立绘姿势 + 表情格 + 文案"三元组。

碎碎念台词池直接用了同人共识里的母题台词——"不是约会，只是看看书""我平时就很好""赛博教会那一套我早就受够了"，来源见 `docs/claude-chan-digest.md`（在隔壁 claude-chan-design 项目）。

## 5. 坐标、尺寸与缩放（踩过的四个坑）

真实 bug，都靠日志定位，记在这里免得重犯：

1. **单位混了**：这台机器 150% 缩放（`--device-scale-factor=1.5`），Electron 的 `screen`/`setPosition` 全走 DIP，而我拿物理像素的截图去对坐标。DIP 下 y=675.9 换算回物理像素正好是站在任务栏上沿。**桌宠定位一律用 Electron 的 DIP 坐标思考，不要用截图像素反推。**

2. **窗口被自己的素材撑大**：正面 392×457、侧面 314×457、背面 357×457——三个视图**宽高比不同**。最初我让窗口跟着"当前显示的立绘"改尺寸，于是一换姿势窗口就跳一次（280x343 ↔ 280x401），宠物跟着跳、可放置范围忽大忽小。**修法：窗口只按正面立绘定一次并锁死；显示尺寸以高度为基准（三视图等高，侧身变窄才是对的）。**

3. **每 2 秒下沉 1px**：Windows 对无边框窗口的实际尺寸总比请求值大 1~2px，而自愈逻辑写的是"保持底边不动"，于是每次"修正"都把误差往下推一次——宠物会慢慢沉到站立线以下。**修法：自愈加 2px 容差；重定位交回站立线夹取，不自己算底边。**

4. **NaN 崩主进程**：`win.setPosition(NaN)` 会抛 `TypeError: conversion failure`，主进程直接崩掉、桌宠消失。**修法：`place()` 拒绝非有限值并自愈；IPC 入参逐个校验；每帧自净 vx/vy/walkTarget；tick 包 try/catch；再加 `uncaughtException` 兜底——常驻小工具绝不能弹崩溃框。**

自检模式（`--selftest`）是验证手段：窗口自己 `capturePage()` 落图，不碰用户桌面。GUI 应用没法靠 `node --check` 验证"到底画出来没有"。

## 6. 自检模式

GUI 应用没法靠 `node --check` 验证"到底画出来没有"，而截用户桌面既慢又打扰。所以内置了 `--selftest`：窗口自己 `capturePage()` 落两张图（待机 + 气泡态）再退出。这是本项目验证渲染的标准手段。
